# Деплой «Лакомки» на обычный сервер (Apache + PHP)

Пакет содержит **готовый к загрузке сайт**: статические HTML/JS/CSS
витрины + PHP-бэкенд с базой SQLite. Node.js на сервере **не нужен**.

## Что внутри

| Путь | Что это |
|------|---------|
| `index.html`, `/catalog/`, `/product/…` | Витрина — статика, сгенерированная Next.js на этапе сборки (товары уже «запечены» в HTML) |
| `/_next/`, `/uploads/`, `/pdfjs/`, `/fonts/` | Ассеты: код, картинки товаров (WebP), PDF-просмотрщик, шрифты |
| `/backend/` | PHP-приложение: приём заказов, PDF, категории. Наружу доступен только `backend/public/index.php` (остальное закрыто `.htaccess`) |
| `/backend/storage/database.sqlite` | База: товары, составы, настройки, SMTP |
| `/update.html` | Страница обновления сайта (доступна также по адресу `/update`): вход по учётке админа и загрузка архива обновления |
| `/.htaccess` | Маршрутизация: `/api/*` → PHP, защита, 301 со старых WordPress-адресов, кэш |
| `/404.html` | Страница 404 |

## Требования к серверу

- Apache с **mod_rewrite** и `AllowOverride All` (чтобы работал `.htaccess`).
- **PHP 8.2+** с расширениями: `pdo_sqlite`, `openssl`, `mbstring`, `gd`, `zip` (стандартный набор любого хостинга; `zip` нужен для обновления сайта архивом).
- Диск: ~300 МБ.
- Права на запись для PHP также в **корень сайта** (нужно для применения обновлений архивом).

## Установка (3 шага)

1. **Загрузите всё содержимое пакета в корень сайта**
   (обычно `public_html/` или `www/домен/`). Сохраните структуру папок.
2. **Права на запись** для PHP — папке базы и логов:
   `backend/storage/` (файл `database.sqlite` + создаваемые там же
   журналы). На большинстве хостингов права по умолчанию уже подходят.
3. **Откройте сайт** — витрина работает сразу, заказы кладутся в SQLite
   и дублируются письмом на почту менеджера (SMTP уже настроен в базе).

Проверка после загрузки:
- `/` — главная, `/catalog/` — каталог с товарами;
- положите товар в корзину и оформите заказ — номер заказа должен
  появиться, письмо уйти; в `backend/storage/database.sqlite`
  появится запись в таблице `orders`;
- `/api/products` — должен вернуть JSON (это PHP).

## Как обновлять товары

Витрина — статика: товары «запечены» в HTML на момент сборки.
Схема работы:

1. Товары/составы/картинки меняются в админке рабочей песочницы.
2. Запускается пересборка: `bash scripts/build-static.sh` — получается
   свежий `download/lakomka-deploy-static.zip`.
3. ZIP распаковывается поверх корня сайта (с заменой).

Заказы при этом не трогаются — они живут в `backend/storage/`
на сервере, а пакеты содержат базу только как «стартовую».
**Важно:** при первом деплое база из пакета создаётся на сервере;
при последующих обновлениях НЕ перезаливайте
`backend/storage/database.sqlite` поверх существующей — иначе
потеряете заказы, накопившиеся на сервере. Обновлять нужно только
`_next/`, HTML-страницы и `uploads/` (и .htaccess при изменении).

## Обновление сайта (архив обновления)

Есть два вида архивов (оба собираются в песочнице):

| Архив | Что несёт | Когда использовать |
|---|---|---|
| `lakomka-deploy-static.zip` | Вся статика + **все медиа** + база (каталог, SMTP) | Первый деплой; смена домена; переезд на другой хостинг |
| `lakomka-update-<версия>.zip` | Только функционал: страницы, стили, скрипты, `.htaccess`, PHP. **Без медиа и без базы** | Все остальные случаи — лёгкий архив |

**Как применить архив обновления** (медиа и накопленные заказы остаются
нетронутыми — они на сервере, а в архив их просто нет):

1. Откройте `https://ваш-домен/update` (или `/update.html`), войдите
   с учёткой администратора — той же, что и в админке песочницы.
2. Выберите файл `lakomka-update-…zip`, нажмите «Обновить сайт».
   Архив загружается по частям — лимиты хостинга на размер запроса не важны.
3. Скрипт распакует архив во временную папку, перезапишет файлы сайта,
   а папку `uploads/` и `backend/storage/database.sqlite` не тронет даже
   если они случайно попали в архив.
4. На странице появится отчёт: сколько файлов обновлено, версия сборки.

### Обновление с GitHub (кнопка «Проверить обновления (ГИТ)»)

На той же странице `/update` есть карточка **«Обновление с GitHub»**:
кнопка проверяет последний релиз в репозитории `Sayikoro/lakomka`,
скачивает архив обновления прямо с сервера GitHub и применяет его —
вручную ничего скачивать и загружать не нужно.

- Медиа и база данных так же не затрагиваются.
- Проверка идёт через api.github.com (без токена — 60 запросов в час
  с одного IP; результат кешируется на 60 с). Если хостинг упирается
  в лимит, положите PAT-токен в `backend/storage/github-token.txt`.
- Скачивание идёт с `github.com/…/raw/<тег>/updates/…`; если raw
  недоступен — автоматически из tar.gz тега (codeload.github.com).
- Целостность: ZIP проверяется (манифест + контрольная сумма),
  затем применяются те же защиты, что и у ручной загрузки.

То же самое умеет вкладка **Настройки → «Обновление»** в админке песочницы
(для тестов: в песочнице обновление применяется к стенду, путь задаётся
файлом `backend/UPDATE_ROOT`). Журнал обновлений: `backend/storage/last-update.json`
на сервере; версия пакета: `backend/version.json`.

**Важно про товары:** архив обновления несёт свежие HTML-страницы, но
**не переносит базу**. Если менялись товары/цены — сначала попросите
«архив обновления с синхронизацией каталога» либо перезалейте полный
деплой-пакет: корзина и заказы считают цены из базы на сервере.
Ручной способ (если страница /update недоступна): распаковать
`lakomka-update-…zip` в корень сайта с заменой — при этом НЕ перезаписывать
`backend/storage/database.sqlite`.

## Админка

В статический пакет **админка не входит** (она требует серверного
Node.js): управление товарами выполняется в песочнице с последующей
пересборкой статики (см. выше). Просмотр заказов, принятых сервером:

- письма о заказах приходят на SMTP-ящик из настроек базы;
- либо быстро смотреть базу можно любым SQLite-клиентом,
  скачав `backend/storage/database.sqlite` по SFTP.

## Настройки домена и почты

- Домен сайта: `https://lakomkakhv.ru` зашит в метаданные на этапе
  сборки (env `NEXT_PUBLIC_SITE_URL`). Если домен другой — скажите,
  пересоберу пакет с нужным адресом.
- SMTP (отправка писем о заказах): настройки уже в базе
  (`backend/storage/database.sqlite`, таблица `settings`,
  ключи `smtp_*`). Меняются через админку песочницы → пересборка
  пакета, либо правкой базы на сервере.

## Частые проблемы

| Симптом | Причина / лечение |
|---|---|
| `/api/*` отдаёт 404 | Не включён mod_rewrite или `.htaccess` игнорируется (`AllowOverride None`) — включите в панели хостинга |
| 500 на всех страницах | Проверьте `backend/storage/php-errors.log` — чаще всего нет расширения `pdo_sqlite` или прав на `storage/` |
| Сайт открылся, но без стилей | Загружены не все файлы — в пакете обязателен `_next/` целиком |
| Письма не уходят | Проверьте `smtp_*` в базе и что хостинг не блокирует исходящий 465 порт |
| Каталог пуст | База из пакета не скопировалась: проверьте `backend/storage/database.sqlite` |
