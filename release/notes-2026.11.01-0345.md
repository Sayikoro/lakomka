# Релиз 2026.11.01-0345 (Task 112) — вкладка «Текст на страницах» + второй раунд починки видео

## Текст на страницах — теперь отдельная вкладка админки

- Редактор текстов витрины переехал изнутри «Настроек» в **вкладку верхнего
  уровня «Текст на страницах»** (видна после «Файлы»; доступна редактору и
  супер-админу). В «Настройках» остались «Основные», «Обновление» и «Журнал».
- **Главное — тексты теперь реально применяются на сайте без пересборки.**
  Раньше сайт — статический экспорт: адрес в футере сохранялся в базу, но
  HTML был запечён при сборке, и футер продолжал показывать старое. Теперь
  витрина после открытия страницы добирает свежие тексты с
  `/api/settings/public` и подменяет их (футер, заголовки, подписи — всё,
  что в реестре текстов). Пока API не ответил — показываются запечённые
  значения, поэтому для поисковиков ничего не пустеет.
- Проверено на статическом стенде: HTML собран без тестового адреса, в
  браузере адрес появился сразу после открытия страницы; правка через UI
  («Сохранить» → «✓ Сохранено») — тоже без пересборки.
- Право записи текстов ужесточено до редактора+: роль «Просмотр» больше
  не может менять витрину (по определению только смотрит).

## Видео: второй раунд — диагностика и запасные попытки

- **Ответ админу больше не содержит информационного шума ffmpeg.** В прошлом
  раунде при полном провале каскада в сообщение попадала первая попавшаяся
  строка лога x264 — приветствие кодера «using SAR=1/1», которое ошибкой не
  является. Теперь строки приветствия (SAR, cpu capabilities, профиль,
  версия, конфигурация) отбрасываются; ищутся настоящие причины — от
  «width not divisible by 2» до «Too many packets buffered», «Decoder not
  found», «Cannot allocate memory», обрывов декодирования и т.п. Если
  настоящую причину выцепить не удалось — сообщение честно говорит об этом.
- **Каскад расширен до 11 попыток** (было 7): добавлены попытки с увеличенным
  буфером муксера (`-max_muxing_queue_size 2048` — классика старых ffmpeg 4.x),
  однопоточные (`-threads 1` — минимум памяти под буферы кадров, для слабых
  хостингов) и финальная вовсе без видео-фильтров. Прежние рабочие попытки
  не изменены.
- **Отладочный журнал `backend/storage/media-debug.log`:** каждая неудачная
  попытка и полная диагностика (-f null, подробный лог) пишутся на диск с
  timestamp'ами. Если «Сжать» не справится и в следующий раз — в журнале
  будет полная фактура с сервера, а не одна строка в ответе админу.
- Реальный присланный файл (LA_v006.mov, iPhone HEVC yuvj420p) по-прежнему
  конвертируется на всех версиях ffmpeg 4.1–7.1; полный регресс
  отказоустойчивости — 10/10, новые тесты диагностики — 12 кейсов, итого
  21/21.

## Мелочи

- Редактор текстов: кнопка «Сохранить» и бейджи «свой текст» переведены с
  ref на состояние (надёжнее при перерисовках), подсказка в редакторе
  сообщает, что текст попадает на витрину без пересборки.
