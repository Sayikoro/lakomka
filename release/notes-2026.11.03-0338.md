# Производительность витрины + починка прелоадера (v2026.11.03-0338)

## Что сделано

**Прелоадер со смешными фразами.** На медленной связи (телефон, слабый сигнал) навигация
срывалась в полную перезагрузку страницы: запрос данных новой страницы застревал за
тяжёлыми картинками, Next.js откатывался к жёсткому переходу — и прелоадер «мигал и умирал»,
а страница грузилась заново с нуля. Причина — вес страниц. После оптимизаций прелоадер
живёт всю навигацию и прячет её: проверено автоматическим тестом с эмуляцией Slow 4G.

**Вес главной страницы: −2,7 МиБ (−86%) по главным картинкам:**
- Фон блока «Как мы работаем»: PNG 1,9 МБ → WebP 119 КБ (−94%)
- Hero (главная картинка экрана): JPG 623 КБ → WebP 239 КБ (−62%); прежний /hero-bg.jpg
  тоже пережат (342 КБ) — для сайтов, где он сохранён в настройках
- Картинка категории «Тубы» (внешний PNG 719 КБ с lakomkakhv.ru) → локальный WebP 85 КБ

**LCP (отрисовка главного контента):** hero-картинка теперь без скелетона, с высоким
приоритетом загрузки (fetchPriority=high) и preload — браузер рисует её сразу по приходу
байтов, не дожидаясь выполнения JavaScript. Ожидаемо на телефоне: LCP с 16,7 с до ~3-4 с.

**Кэширование (повторные визиты быстрее):**
- JS-чанки Next.js получили кэш на 1 год (раньше отдавались вообще без кэша — Apache
  помечает их как text/javascript, а правило было только для application/javascript)
- Шрифты и иконки — кэш на месяц (раньше — без кэша)
- Страховка через mod_headers на случай хостингов без mod_expires
- RSC-полезные нагрузки (файлы *.txt, до 776 КБ) теперь сжимаются DEFLATE (~5-6×)
- HTML по-прежнему всегда свежий (после обновления сайта браузер не держит старую версию)
