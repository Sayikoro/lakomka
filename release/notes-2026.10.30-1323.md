Лакомка v2026.10.30-1323 — «Сжать» находит видео, даже если ссылка устарела

ГЛАВНОЕ
1. Исправлена ошибка «не удалось перекодировать видео (ffmpeg:
   …/uploads//файл.mov: No such file or directory) — оставлен исходный
   файл», с которой сталкивались на реальном хостинге. Она возникала,
   когда файл по записанной в базе ссылке уже отсутствовал: видео
   перекодировано ранее (например, «Сжать» нажали дважды, и первый
   запрос успел отработать), файл перемещён по FTP или удалён вручную.
2. Теперь при промахе по точному пути «Сжать» ищет файл по ВСЕМУ
   дереву /uploads (как импорт, Task 85):
   - найден тот же файл в другой папке — сжимается он, ссылки товаров
     переписываются на новое место;
   - найден готовый MP4 с тем же именем — сервер отвечает «видео уже
     было перекодировано ранее», ссылки товаров обновляются на MP4
     одной кнопкой (чинит и устаревшие ссылки с двойным слэшем);
   - файла нет нигде — понятное сообщение «Файл … не найден в /uploads
     — возможно, он удалён или уже перекодирован» вместо техношума ffmpeg.
3. Устранена гонка двойного нажатия «Сжать»: второй запрос больше не
   падает с ошибкой ffmpeg, а возвращает уже готовый MP4 и обновляет
   ссылки.
4. Мелкое: пути с двойными слэшами («uploads//файл.mov») нормализуются
   — ни в сообщениях, ни в ссылках двойные слэши больше не появляются;
   ссылка в базе после сжатия всегда чистая.
