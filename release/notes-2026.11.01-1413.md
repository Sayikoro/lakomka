# Обновление 2026.11.01-1413 (Task 120)

## Картинки блока «Процесс оформления и обработки заказа» — самовосстановление

Диагноз тот же, что у снежинки (Task 118): иконки шагов (`ico-step1..3.svg`),
фон (`process-bg.png`), снежинка и логотип — файлы, на которые ссылается КОД
витрины, а не база. Они были удалены на сервере ещё до появления защиты, а
механизм восстановления из Task 118 срабатывал только при ПРИМЕНЕНИИ пакета
обновления — если обновление не применить, файлы не возвращались.

### Что нового

1. **Самовосстановление при старте API** — `SystemFiles::ensureHealed()` вызывается
   при первом же запросе к API (`Bootstrap::ensure`). Быстрый путь — один `is_file`
   на файл; копирование только если чего-то не хватает. Обновление кода = файлы
   витрины возвращаются сами, ждать «применить пакет» не нужно.
2. **`heal()` понимает обе раскладки** — деплой (`uploads/` в корне) и репозиторий
   (`public/uploads/`).
3. **Иконки шагов вшиты в код** — `ProcessSteps.tsx` при недоступности
   `/uploads/ico-stepN.svg` рисует иконку из встроенного data-URI
   (`stepIconFallbacks.ts`, сгенерирован из копий ассетов). Блок «Процесс
   оформления» больше не зависит от наличия файлов на диске — тот же приём,
   что у дефолтной снежинки снегопада.

### Что нужно сделать владельцу

**Просто примените обновление** (админка → Настройки → «Обновление» → «Проверить
обновления (ГИТ)» → применить). После обновления все 6 системных файлов будут
дописаны на сервер автоматически, и картинки блока, снежинка и логотип
восстановятся — дополнительно ничего делать не нужно.
