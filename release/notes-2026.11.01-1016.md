# v2026.11.01-1016 — снежинки в херо-блоке снова летают (Task 118)

## Что случилось

После очистки «Неиспользуемых файлов» (файловый менеджер → «Неиспользуемые»)
с херо-блока главной страницы пропали снежинки: вместо них падали мутные
кружочки. Одновременно были сломаны логотип в шапке, картинки и фон блока
«Как мы работаем» — все они на проде отдавали 404.

Причина: у этих файлов ссылки зашиты в КОДЕ витрины (снегопад, шапка,
ProcessSteps), а не в базе данных. Сканер «неиспользуемых» сверяет файлы
только с базой — файлы без ссылок в БД он честно (но ошибочно) считал
мусором, и очистка убрала их в корзину.

## Что сделано

1. **Системные файлы витрины защищены** (backend/src/SystemFiles.php):
   `/uploads/snowflake/snowflake.svg`, `/uploads/brand/logo-lakomka.webp`,
   `/uploads/ico-step1..3.svg`, `/uploads/process-bg.png` больше не
   появляются в отчёте «Неиспользуемые», массовая очистка их пропускает,
   точечное удаление файла или папки с ними — отказ (403).
2. **Самовосстановление при обновлении**: копии всех шести файлов едут
   внутри архива обновления (`backend/assets/system-uploads/`). После
   применения обновления сервер дозаписывает отсутствующие файлы в
   `uploads/` — ответ содержит список `system_restored`. Файлы, утерянные
   до выхода этого релиза (снежинка, логотип и т.д.), вернутся сами —
   достаточно применить обновление.
3. **Дефолтная снежинка вшита в код** (src/lib/snow.ts → Snowfall.tsx):
   снегопад больше не скачивает SVG по сети — рисует встроенную снежинку
   даже если uploads пуст. Своя снежинка из настроек по-прежнему грузится
   по ссылке; если её файл недоступен — снова встроенная (кружки-фолбэк
   остались на самый крайний случай). Превью в админке (Настройки →
   Снегопад) тоже больше не зависит от файла в uploads (data-URI).
