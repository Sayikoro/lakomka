# Деплой-архив: как собрать lakomka-deploy-static.zip из частей

GitHub не принимает файлы больше 100 МБ, поэтому архив
`lakomka-deploy-static.zip` (116989824 байт) лежит в репозитории двумя частями:

| Файл | Размер |
| --- | --- |
| `lakomka-deploy-static.zip.part-00` | 94371840 байт |
| `lakomka-deploy-static.zip.part-01` | 22617984 байт |

## Склейка

Скачайте обе части в одну папку и выполните:

**Windows (cmd):**

```
copy /b lakomka-deploy-static.zip.part-00+lakomka-deploy-static.zip.part-01 lakomka-deploy-static.zip
```

**Linux / macOS:**

```
cat lakomka-deploy-static.zip.part-00 lakomka-deploy-static.zip.part-01 > lakomka-deploy-static.zip
```

## Проверка целостности

sha256 собранного файла должен совпадать:

```
4c0c1c83dc0c77ad933f6666b2fdf2ce1284388ae579d979250d954b734b938a
```

- Windows PowerShell: `Get-FileHash lakomka-deploy-static.zip -Algorithm SHA256`
- Linux / macOS: `sha256sum lakomka-deploy-static.zip`

## Что дальше

1. Распаковать архив в корень сайта (Apache + PHP 8.2+, Node не нужен).
2. Следовать инструкции `README-DEPLOY.md` внутри архива (исходник — `scripts/deploy/README-DEPLOY.md` в репозитории).

Актуальный пакет: статическая витрина + ВСЕ медиа + **клиентская админка
(`/admin/`)** + backend (PHP + SQLite: каталог, настройки, SMTP) + `.htaccess`
+ страница обновления `/update` + смешная страница 404. Первый вход в
админку: `admin@lakomka.local` / `Lakomka2026!` (суперадмин уже в базе,
секретные ключи генерируются автоматически; после смены пароля подсказка
на странице входа исчезает).

Последующие обновления функционала — архивы `lakomka-update-<версия>.zip`
(без медиа и без БД: собираются командой `MODE=update bash scripts/build-static.sh`,
в git не складываются, загружаются через Настройки → «Обновление» или `/update`).

**Важно про вход в админку на давно работающем сайте (с версии 2026.10.30-0507):**
дефолтный суперадмин `admin@lakomka.local` создаётся в базе автоматически при
первом же запросе к сайту, даже если база старая (обновления кода базу не
трогают). Если вход выдаёт «Неверный email или пароль» — установите это
обновление, обновите страницу входа и войдите дефолтными кредами; пароли
существующих учёток и все заказы не затрагиваются.

**Файловый менеджер на развёрнутом сайте (исправлено в 2026.10.30-0557):**
в проводнике `/admin/files` при клике на раздел/папку раньше появлялось
«Раздел недоступен»: PHP искал медиа в `public/uploads` (раскладка dev-проекта),
а в деплой-пакете `uploads/` лежит в корне сайта. Теперь бэкенд сам определяет
раскладку (backend/src/Paths.php) и создаёт недостающие каталоги — проводник,
загрузка картинок товаров, hero-слайдов, PDF и экспорт работают и на сервере.
Если сайт развёрнут из более старого архива — поставьте обновление
2026.10.30-0557 (медиа и база не затрагиваются).

**Снегопад и оптимизатор медиа (новое в 2026.10.30-0632):**
(1) Снегопад больше не «запекается» в страницы при сборке: главная сама
подтягивает свежие настройки с `/api/settings/public` — включили снег в
админке → обновили главную страницу → снег идёт (пересборка не нужна).
(2) Исправлена ошибка сохранения настроек «hero_slider_enabled: 0 | 1»:
бэкенд принимает любые варианты вкл/выкл (true/false, on/off и т.д.).
(3) Автооптимизатор загрузок: картинки JPG/PNG сжимаются в WebP (максимум
2000px, тест: 369 КБ → 16 КБ), видео MOV/M4V конвертируется в MP4 без потери
качества (или перекодированием в H.264, если внутри редкий кодек) — работает
в карточке товара, медиа-галерее и проводнике; mp4/webm/GIF/SVG не трогаются.
Если на хостинге нет ffmpeg — видео сохраняется как есть (админка покажет
заметку). Попутно: привязка из галереи принимает русские имена файлов,
лимиты: картинки до 32 МБ, видео до 200 МБ.

**Видео из галереи, дампы БД и живой hero (новое в 2026.10.30-0715):**
(1) Ошибка «Допустимы только файлы из /uploads/» при добавлении файла из
галереи в товар убрана: файл можно привязывать из любой своей папки с любым
именем (защита — на проверке реального пути, а не на символах имени).
(2) В медиа-галерее вкладка «Видео» теперь ищет ВСЕ видео по всем папкам
/uploads сразу (новее сверху); если хочется смотреть только свою папку —
впишите её в поле «папка видео» и нажмите «Запомнить и искать»: настройка
сохранится, и галерея при следующих открытиях будет показывать видео из неё.
(3) Миграции базы данных с автоматическим дампом: перед каждым изменением
структуры БД сайт сам сохраняет копию базы в `backend/storage/backups`
(последние 10 штук; посмотреть и скачать — проводник → раздел «Дампы базы
данных»). Структуру базы теперь можно дорабатывать без риска потерять заказы.
(4) Картинка hero появляется на сайте после обновления главной страницы (F5)
без пересборки — как и снегопад. Если загрузка hero-фото с iPhone не
проходит (HEIC) — сохраните фото как JPG и загрузите снова.

**Живая витрина и видео без 503 (новое в 2026.10.30-0853):**
(1) Каталог, плитки категорий и страницы товаров теперь ДИНАМИЧЕСКИЕ:
витрина стартует с запечённых при сборке данных (мгновенно, для SEO),
затем сама подтягивает свежие товары/цены/фото/видео с `/api/products` —
всё, что вы добавили в админке на сервере, появляется на витрине после
обновления страницы (F5), пересборка не нужна.
(2) Товары, созданные ПОСЛЕ сборки пакета, открываются по прямой ссылке:
если статической страницы нет, 404-страница сама находит товар в API и
показывает полноценную карточку (в URL остаётся адрес товара).
(3) Видео в карточках каталога и на страницах товаров работает: превью
при наведении/слайды с видео, у карточек — значок ▶.
(4) Исправлена ошибка 503 на видео (.mov/.mp4): в `.htaccess` теперь
явное правило — всё содержимое `/uploads/` отдаётся Apache напрямую,
мимо PHP (параллельные превью видео больше не выедают лимит процессов
хостинга), плюс корректные MIME-типы для mov/mp4/webm/webp/avif.
Если на вашем сайте `.htaccess` редактировался вручную — сравните его
с версией из архива (обновление применит новую версию автоматически).
Ограничение честно: новые товары появляются в sitemap.xml и получают
обычный 200-статус для поисковиков после очередной пересборки пакета.

## Обновления через GitHub (основной канал с версии 2026.10.30-0411)

Архивы обновлений больше не пересылаются вручную. Каждый релиз:

1. Собирается `MODE=update bash scripts/build-static.sh`.
2. Публикуется командой `bash scripts/gh-release.sh download/lakomka-update-<версия>.zip [notes.md]` —
   ZIP коммитится в тег `v<версия>` (`updates/lakomka-update-<версия>.zip`),
   к тегу создаётся релиз с заметками.
3. Ставится на сайт кнопкой **«Проверить обновления (ГИТ)»** на странице
   `/update` (или в админке песочницы): сайт сам находит последний релиз,
   скачивает архив (`github.com/…/raw/<тег>/updates/…`, резерв — tar.gz тега
   через codeload.github.com), проверяет манифест и sha256 и применяет.
   Медиа и база данных не затрагиваются.

Разовый переход: один раз примените `lakomka-update-2026.10.30-0411.zip`
(или новее) вручную — после этого кнопка проверки работает на сайте.
